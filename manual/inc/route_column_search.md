# 巡回車別の経路候補組合せ探索

対象: [`inc/route_column_search.hpp`](../../inc/route_column_search.hpp)

`searchRouteColumns()`は、既存の合法な日次計画を起点に巡回車ごとの完成経路候補を作り、各車から1本ずつ選ぶ。既存の補給車経路を固定した案に加え、補給車1台を需要の高いスポットへ移動させて待機する案も調べる。補給計画を固定したうえで各巡回車の経路を単独でシミュレーションし、候補が取得するスポットと系列、玉数、燃料を記録する。

候補生成には既存経路の行動境界までの前半を残して後半に訪問先を追加・入替する方法と、スポット列を独立に伸ばす方法を併用する。候補の切詰めと組合せ順序では、試合で未取得の系列、他車がまだ担当していない当日系列、玉数、燃料を順に評価する。巡回車ごとの候補上限は新規探索枠とし、既存計画の経路が漏れた場合は安全候補として別枠で保持する。組合せ探索ではスポットごとの残在庫を超える組合せを除外し、残る系列・玉数の上限で枝刈りする。候補間の相互作用を単独シミュレーションだけでは確定できないため、改善候補は全車・全ステップを公式順序で再シミュレーションし、合法で採用条件を満たす場合だけ置き換える。

比較は試合系列数、当日系列数、玉数の辞書順を基本とする。中間日は翌日の系列到達性・距離・残燃料の近似条件も適用する。系列数を増やすために玉数を減らす場合があり、両方の同時増加を保証しない。経路候補と補給地点は有限個で、時間・燃料・在庫を含む大域最適性も証明しない。

`RouteColumnConfig`の既定値は、`enabled=true`、日次予算の下限`minimumBudgetMs=5000`、候補生成の`labelWidth=24`、巡回車あたり`columnsPerAgent=32`、最大訪問数`maxVisits=14`、組合せ探索上限`maxMasterNodes=150000`、補給車待機案`supplyRendezvous=true`。`brain1()`ではスポット系探索が有効で、日次予算が5秒以上あり、従来のスポット再探索後に時間が残る場合だけ呼び出す。その後、さらに時間があれば玉数ALNSを試す。CLIの`--route-columns 0/1`で追加探索を切り替えられる。`--spot-route-lns 0`なら追加探索も停止する。

結果の`generated`は生成した経路候補数、`masterNodes`は組合せ探索の訪問ノード数、`improvements`は採用改善数を表す。`brain1()`の`routeColumnsGenerated`、`routeColumnsMasterNodes`、`routeColumnsImprovements`、コンソール統計、ベンチマークCSVへ伝播する。締切・候補なし・改善なしでは入力計画を保持する。呼び出し元と採用順は[`brain1.hpp`](brain/brain1.md)、生成問題でのON/OFF比較は[2026-10-05の検証記録](../tests/route-column-results-2026-10-05.md)、公開試合 API を使った候補保持の比較は[2026-10-06の検証記録](../tests/arena-api-results-2026-10-06.md)を参照する。
