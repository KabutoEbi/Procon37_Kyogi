# 巡回車別の経路候補組合せ探索

補給車の時刻付き合流も探索する。既存計画から燃料不足の大きい巡回車の位置・時刻を抽出し、補給車が間に合う最大3地点の合流計画を作る。同一位置・時刻の需要は重複を除き、複数巡回車の不足燃料を合算して共有合流を優先する。各補給計画の下で全巡回車の経路候補を作り直すため、補給位置だけを変更して終了しない。`maxSupplySchedules`は既定8、1計画の`maxMeetingsPerSchedule`は既定3。候補は有限個であり、全補給時刻・全経路の厳密な同時最適化ではない。

対象: [`inc/route_column_search.hpp`](../../inc/route_column_search.hpp)

2026-10-07: 追加合流候補は不足燃料×補給後の残り時間で優先する。標準の`coordinatedRefinement`でも追加補給候補を有効にし、共同経路生成に時間を確保する。中間日の採用条件には燃料を考慮した翌日到達性と動けない巡回車数を追加した。

`searchRouteColumns()`は、既存の合法な日次計画を起点に巡回車ごとの完成経路候補を作り、各車から1本ずつ選ぶ。既存の補給車経路を固定した案に加え、すべての補給車について需要の高いスポットへ移動して待機する案を評価する。到達可能な巡回車の予測不足燃料、補給後に残る活動時間、利用できる在庫、補給車の移動時間で順位付けし、予測利用者がいない地点は除外する。固定待機案は既定で上位2件に抑え、残りの補給計画枠を時刻付き複数合流へ残す。補給計画を固定したうえで各巡回車の経路を単独でシミュレーションし、候補が取得するスポットと系列、玉数、燃料を記録する。

候補生成には既存経路の行動境界までの前半を残して後半に訪問先を追加・入替する方法と、スポット列を独立に伸ばす方法を併用する。32×32では、指定した目的店だけでなく復元した最短経路上で通過する店もラベルの取得数・系列へ加える。完成後の公式シミュレーションだけに通過取得を任せると、実際には多く取得できる経路が幅24の途中で消えるためである。24×24の比較では得点増加が確認できなかったため、未検証の16×16を含む小中盤面は保守的に従来順位を維持する。巡回車別の候補枠は玉数の多い経路を先に確保し、系列の異なる経路と他車が使わない在庫に寄与する経路も残す。系列数最大を補う最良系列経路と既存計画の経路は候補枠の外でも保持する。組合せ探索でもまず玉数の多い経路を試すが、系列数は全エージェントの経路を組み合わせてから判定する。足りなければ保持した系列経路との組合せを調べる。スポットごとの残在庫を超える組合せは除外し、残る系列・玉数の上限で枝刈りする。候補間の相互作用を単独シミュレーションだけでは確定できないため、改善候補は全車・全ステップを公式順序で再シミュレーションし、合法で採用条件を満たす場合だけ置き換える。

最終採用は試合系列数、当日系列数、玉数の辞書順で行い、既存計画の系列数を落とさない。中間日は翌日の系列到達性・距離・残燃料の近似条件も適用する。系列数を増やすために玉数を減らす場合があり、両方の同時増加を保証しない。ここでの「最大」は前段の系列探索で確認できた最良系列数で、`brandOptimal=true`の場合に限り当日の最適性が証明済みとなる。経路候補と補給地点は有限個で、時間・燃料・在庫を含む大域最適性も証明しない。

`RouteColumnConfig`の既定値は、`enabled=true`、日次予算の下限`minimumBudgetMs=5000`、候補生成の`labelWidth=24`、巡回車あたり`columnsPerAgent=32`、最大訪問数`maxVisits=14`、組合せ探索上限`maxMasterNodes=150000`、32×32の通過取得順位`rankTransitPickups=true`、補給車待機案`supplyRendezvous=true`、補給計画数`maxSupplySchedules=8`、固定待機案`maxStationSchedules=2`、1計画の最大合流数`maxMeetingsPerSchedule=3`。`brain1()`ではスポット系探索が有効で、日次予算が5秒以上あり、従来のスポット再探索後に時間が残る場合だけ呼び出す。その後、さらに時間があれば玉数ALNSを試す。CLIの`--route-columns 0/1`で追加探索を切り替えられる。`--spot-route-lns 0`なら追加探索も停止する。

結果の`generated`は生成した経路候補数、`masterNodes`は組合せ探索の訪問ノード数、`improvements`は採用改善数を表す。`brain1()`の`routeColumnsGenerated`、`routeColumnsMasterNodes`、`routeColumnsImprovements`、コンソール統計、ベンチマークCSVへ伝播する。締切・候補なし・改善なしでは入力計画を保持する。呼び出し元と採用順は[`brain1.hpp`](brain/brain1.md)、生成問題でのON/OFF比較は[2026-10-05の検証記録](../tests/route-column-results-2026-10-05.md)、公開試合 API を使った候補保持の比較は[2026-10-06の検証記録](../tests/arena-api-results-2026-10-06.md)を参照する。
