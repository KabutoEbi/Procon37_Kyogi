# `trial.hpp` の使い方

対象: [`inc/trial.hpp`](../../inc/trial.hpp)

エージェント種別や評価重みを比較するため、再現可能な交通条件で複数日をオフライン試走する。

```cpp
auto scenarios = benzen::makeTrialScenarios(setting, 3);

benzen::BeamSearchConfig beam;
beam.beamWidth = 32;
beam.jointBeamWidth = 128;

auto trial = benzen::runTrial(
    setting, kinds, scenarios.front(), beam, 2);

if (trial.success) {
    benzen::TrialScore score = benzen::trialScore(trial.score);
}
```

`TrialTraffic`は`[day][cell]`の道路状態、`TrialScore`は公式優先順の`{試合系列数, 累積日別系列数, 玉数}`である。`dayLimit=0`なら全日を実行する。

`makeTrialScenarios()`はチーム数、1チームのエージェント数、直前の日程のステップ数、通行可能セル数、道路判定閾値から道路状態を予測する。公式ルールに合わせて初日は全道路を順調とし、2日目は前日、3日目以降は直前2日分のステップ数を使う。道路は経路に選ばれやすいものとして他の通行可能セルの2倍の滞在重みを与える。

`predictRoadLoad()`が返す平均は全チームの予測滞在量をチーム数で割った値である。同じエージェント数なら平均値ではチーム数が相殺されるが、チームが多いほどチーム平均のばらつきは小さくなる。`makeTrialScenarios()`はこの平均とばらつきから低位・中央・高位の条件を作り、固定された道路ごとの偏りも加える。同じ道路状態になった条件は重複させない。これは開始前に取得できる設定だけを使う予測であり、各チームの実際の経路を予言するものではない。

試走中は`MatchState::endsAt`による締切を無効化し、各日の予測道路状態だけを探索に与える。`BeamSearchConfig::timeLimitMs`を指定した場合の相対時間制限は有効である。

第6引数へ`std::chrono::steady_clock::time_point`の試走全体の締切を渡せる。毎日、残り時間を残り日数で割り、日次時間制限との小さい方を使用する。翌日の開始前に期限が切れていれば`success=false`を返すので、呼び出し側は途中までの得点を完走結果と比較しない。省略時の動作は従来どおりである。

同じ種別配置を複数の交通シナリオで試す場合は、第7引数に`TrialFirstDay`を渡すと、直前のシナリオと初日から連続して道路状態が一致する日まで、探索結果・位置・燃料・得点を再利用する。分岐した日以降は再探索し、キャッシュの末尾を置き換える。`reusedDays`はその呼び出しで再利用した日数。互換性のため型名を維持している。

候補配置と探索設定ごとに新しいキャッシュを作る。種別配置、日数、設定オブジェクトのアドレスが異なれば再利用しない。同じ設定オブジェクトの内容や探索重みを変更した場合は呼び出し側でキャッシュを初期化する。期限が切れた試走は未完走になる。時間制限がある場合は、再利用で残り日程の探索時間配分が変わるため、キャッシュなしと同じ得点になる保証はない。
