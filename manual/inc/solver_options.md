# `solver_options.hpp` の使い方

対象: [`inc/solver_options.hpp`](../../inc/solver_options.hpp)

2026-10-07追加: `--coordinated-refinement 0/1`（既定1）は翌日終端準備・先回り補給・玉数改善への時間確保を切り替える。詳細は[翌日配置と補給](overnight_refinement.md)。旧試験機能 `--quantity-upgrades` とは独立。

`SolverOptions::parse(argc, argv)`は`main`の位置引数を保持したまま探索オプションを読み取る。負数、不正な整数、未知のオプション、0のビーム幅を拒否する。値はスペースで区切って指定する。

```sh
./main solve runtime/setting.json runtime/state-day0.json \
  --beam-width 256 --joint-beam-width 1024 --threads 4 \
  --time-limit-ms 10000 --safety-margin-ms 1000
```

| オプション | 対象 |
|---|---|
| `--beam-width`, `--joint-beam-width` | 日次探索幅 |
| `--auto-beam-width` | 盤面・台数・当日ステップ数で幅を選ぶ。1で有効、0で手動。CLI既定は有効だが幅を明示した場合は手動を優先 |
| `--threads` | スレッド数。0は自動 |
| `--time-limit-ms` | 日次相対時間上限。0は指定なし |
| `--safety-margin-ms` | 探索・種別選択で残す締切余裕 |
| `--max-actions` | 各車の行動候補数。0は全候補 |
| `--macro-actions`, `--adaptive-beam` | 有効1、無効0 |
| `--exact-brands` | 1で系列補完の探索件数上限を解除。0は既定の上限付き補完 |
| `--brand-repair` | 系列救済型の連鎖再計画。有効1（既定）、無効0 |
| `--small-board-brand-rescue` | 16×16で系列不足時に修復・全車系列探索を拡張。有効1（既定）、無効0 |
| `--small-board-beam-budget-percent` | 16×16の自動幅ビームへ渡す基準割合。既定75、範囲50〜95。厳燃料時は85を下限にする |
| `--small-board-brand-node-limit` | 16×16の全車系列探索上限。既定200000、最小1000。厳燃料時は100000へ抑え、締切も別に適用 |
| `--small-board-quantity-first` | 16×16・8日・14系列で玉数優先の経路ポートフォリオも比較。有効1（既定）、無効0 |
| `--udon-alns` | 系列マスクを固定した玉数ALNS。有効1（既定）、無効0 |
| `--udon-sa` | 玉数ALNS内の焼きなまし（一時悪化受理）。有効1（既定）、無効0 |
| `--udon-joint-destroy` | SA前に巡回車2〜3台と最寄り補給車を共同再構築。有効1（既定）、無効0 |
| `--adaptive-long-search` | 本選盤面と実効時間に応じたビーム／ALNS配分とALNS上限の調整。有効1（既定）、無効0 |
| `--spot-route-lns` | スポット単位の再割当・経路探索。有効1（既定）、無効0 |
| `--terminal-wait-fill` | 系列を維持したまま巡回車の末尾待機を追加店舗への経路へ置換。有効1（既定）、無効0 |
| `--traffic-aware-joint-routes` | 最終日16×16の残時間で、混雑・渋滞込みの迂回順位、時刻付き給油待ち、巡回車間の末尾交換を比較。有効1（既定）、無効0 |
| `--route-columns` | 巡回車別の経路候補組合せ探索。有効1（既定）、無効0。既定では日次予算5秒以上かつ`--spot-route-lns 1`の場合だけ実行 |
| `--next-day-probe` | 中間日の候補を翌日も短時間試走する実験機能。有効1、無効0（既定） |
| `--quantity-upgrades` | 実験的な玉数改善群を有効化する試験設定。既定0、有効1。日跨ぎ探索は含まない |
| `--quantity-budget-percent` | 玉数探索の予約割合を1〜90で固定し、自動長時間調整を無効化する。比較・診断用 |
| `--day-beam` | 日跨ぎ探索の有効1（既定）／無効0。`--quantity-upgrades`とは独立し、有限予算5秒以上の中間日で動作 |
| `--day-beam-width`, `--day-beam-depth` | 日跨ぎ幅2〜8（既定4）、先読み日数1〜3（既定2） |
| `--day-beam-max-udon-loss` | 先読みに許す当日玉数の減少上限。既定2、0で減少を禁止 |
| `--trial-candidates` | 種別選択で試走する候補数。0は距離評価のみ |
| `--trial-beam-width`, `--trial-joint-beam-width` | 種別選択の試走幅 |
| `--selection-time-ms` | 種別選択の相対時間上限 |

`selectorFor(setting)`で盤面サイズに応じた既定時間上限と`startsAt`の締切を適用する。種別選択の`minSupplyCount`は既定で1で、時間切れ時のフォールバックにも適用される。日次探索では`endsAt`も引き続き有効。オフライン状態で時間オプションを省略した場合、自動幅は60秒の相対上限と5秒の安全余裕により約55秒探索し、手動幅は従来どおり5秒。GUIは入力値を明示的に渡す。

`--auto-beam-width 1`では16×16、24×24、32×32の55秒基準幅44,000、14,300、5,940を使い、間のサイズは補間する。台数、初日と当日のステップ数、相対時間上限に応じて日ごとに幅を調整し、同時行動幅を4倍にする。相対上限は安全余裕を除いて最大55秒に抑え、選択した幅を二重に縮小しないよう従来の適応的幅縮小を停止する。反復深化と後段の玉数探索は残るため、実行時間・得点の厳密な予測や55秒での自然完了を保証する機能ではない。明示的な`--time-limit-ms 0`と、上限指定なしの`--exact-brands 1`は従来どおり無制限を維持する。サーバーの締切と送信余裕は引き続き優先される。GUIはこの自動モードを既定で選び、手動幅にする場合は画面の「ビーム幅の自動選択」を0へ変更する。

`--adaptive-long-search 1`では安全余裕と日跨ぎ予約を除いた実効時間を使い、15秒未満、15〜30秒、30〜45秒、45秒以上の4段階で配分を選ぶ。短い先行探索はビームを厚くし、50秒・55秒級の追走探索では後段のスポット・経路・ALNSを増やす。厳燃料日は時間が長くてもビーム85%を維持する。実際の割合とALNS上限はコンソールの`beam-budget-percent-used`、`quantity-budget-percent-used`、`udon-alns-attempt-limit`、`udon-alns-nodes-per-attempt`で確認できる。

`--next-day-probe 1`は翌日の予測交通で候補を比較するが、実測の2日間取得数で退行したケースがあるため既定では無効。系列マスク維持と翌日到達性の近似検査は、この指定によらず有効である。

16×16の系列救済は、ビーム計画が当日全系列へ届かなかった場合だけ修復を48試行・巡回車3台・5切断点へ広げ、全車系列探索を最大10万状態にする。中間日の修復は翌日到達可能系列と動けない巡回車数を保護する。通常の大盤面探索にはこの拡張を適用しない。

新しい`--day-beam`は[日跨ぎ候補探索](day_beam.md)を参照。動作する場合は旧`--next-day-probe`より優先される。

実験的な玉数改善群は[比較試験](../tests/quantity-search-results-2026-10-06.md)で玉数退行が残ったため、通常実行では無効。予約割合だけを指定してもこの機能群は有効にならず、`--quantity-upgrades 1`を明示して比較する。日跨ぎ探索と、その幅・日数設定はこの機能群から独立している。

`--route-columns 0`は既存のビーム・系列補完・スポット再探索・玉数ALNSを保ったまま、新しい経路候補組合せ探索だけを止める。`--spot-route-lns 0`では新方式も実行しない。候補生成・組合せ探索は有限幅・締切付きであり、系列数と玉数の同時増加を保証しない。

`positional`は元の`argv`へのポインタを保持するため、呼び出し側はその寿命を維持する。

最大系列数を証明するまで探索するオフライン実行例（状態JSONの`endsAt`は0）:

```sh
./main solve setting.json state.json --exact-brands 1 --time-limit-ms 0
```

`--exact-brands 1`ではオフラインの暗黙の5秒制限も解除する。探索時間・メモリは問題によって大きくなる。明示的な時間制限や`endsAt`がある場合は、ビーム探索を有効予算の20%までに抑えて残りを完全探索へ優先配分し、締切を守る。未証明ならレポートの`brand-optimal=false`となる。保証の対象は、指定されたエージェント種別・当日交通に対する「当日終了時の試合系列数、当日系列数」の辞書順最大値。将来の交通が未知の試合全体や種別選択の最適性、獲得玉数の最適性は含まない。

内部では、整数への変換と範囲検査を`parseValue()`、各設定への反映とオプション固有の検査を`setOption()`が担当する。`parse()`は位置引数とオプションの振り分けだけを行う。この分離は内部実装であり、公開APIとエラーメッセージ、既定値は従来どおりである。
