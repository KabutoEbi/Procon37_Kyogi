# `arena_benchmark.cpp` の使い方

対象: [`tests/arena_benchmark.cpp`](../../tests/arena_benchmark.cpp)

公開済みの試合詳細APIから取り出した`problem`を、そのまま`MatchSetting`として
全日程探索するための比較ツールである。リポジトリには外部サイトの問題データを
同梱しない。過去試合の`startsAt`はオフライン測定時だけ0へ置き換える。

```sh
make .build/tools/arena_benchmark
.build/tools/arena_benchmark problem.json 1000 8
.build/tools/arena_benchmark problem.json 1000 8 mixed
.build/tools/arena_benchmark problem.json 5000 17 smooth 128 512 0
.build/tools/arena_benchmark problem.json 1000 16 mixed 128 512 1 1 0
```

設定パスを`-`にすると標準入力から問題JSONを読む。公開APIレスポンスの`problem`だけを渡す例:

```sh
curl -fsS https://procon37arena.online/api/matches/1866 |
  jq '.problem' |
  .build/tools/arena_benchmark - 1000 16 mixed
```

最後から3番目の省略可能引数は公開得点誘導SAのモード。`0`は全て一様、`1`は実験的な近傍確率だけ、`2`は在庫重み付きスポット選択だけ、`3`は両方を有効にする。省略時は既定の`2`相当。

続く省略可能引数は、共同destroy/repair、残在庫・未取得系列の利益と交通込み挿入迂回量を組み合わせるスポット選択、挿入位置の局所差分評価、自動調整ビーム幅として扱うかの有効・無効（各1/0）である。

位置引数は順に、問題JSON、1日あたりの探索上限ms、補給車ビットマスク、
任意の交通モード、ビーム幅、同時行動幅、難所翌日配置の0/1、詳細表示の0/1、
公開得点誘導モード0〜3、共同destroy/repairの0/1、迂回量考慮スポット選択の0/1、挿入位置の局所差分評価の0/1である。
その後に、自動幅として扱うか（0/1）、玉数改善予算（1〜90%、明示すると適応的長時間配分を無効化）、追加SAの訪問列引継ぎ（0/1、既定1）を指定できる。比較時には最後の1値だけを切り替えて他の条件を揃える。
さらに、16×16の3台同時再配分（0/1）、16×16最終日の追加経路組合せ（0/1）を指定できる。
この計測ツールだけは探索時間0を固定探索量として許可し、時間・自動幅調整なしで指定幅を使用する。本番の無制限運用を推奨する意味ではない。
ビット`i`が1ならエージェント`i`を補給車にする。
補給車0台も指定できるが、全車を補給車にはできない。`mixed`は道路セルだけを対象に、
日・位置から再現可能な混雑20%、渋滞10%の条件を生成する。指定しなければ
全道路順調である。
`mixed-after-first`は初日だけ全道路順調とし、2日目以降を`mixed`と同じ固定交通にする。公式の初期道路条件に合わせて過去問題を比較する場合はこちらを使う。

標準出力は日ごとの累積`kinds/daily_kinds/balls`、当日系列ビットマスク、探索時間、展開数と、
最終的な辞書順スコアを出す。アリーナの実戦結果には他チームによる在庫取得と、
直前2日間の道路利用から決まる交通が含まれるため、ローカル値との完全一致ではなく、
系列達成率、日別系列達成率、玉数の水準を比較する。
