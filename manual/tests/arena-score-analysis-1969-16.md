# 公開試合1969と16×16玉数優先経路

## 公開結果

公開試合1969は16×16、4エージェント、8日、14系列である。公開結果の首位は`14/112/182`、うどんは`14/112/181`、超10Gは`14/108/154`だった。超10Gは試合系列こそ満点だが、8日すべて14系列の理論値112に4不足し、首位より28玉少ない。

## 探索方針

#1969と同じ16×16・8日・14系列に限り、既存計画を保持したまま玉数優先の全巡回車経路ポートフォリオを追加比較する。

1. 取得玉数、新規試合系列、当日系列、移動量の順で有限幅ビームを展開する。
2. 公式シミュレータで試合系列・当日系列が盤面の全系列数へ達した候補だけを採用する。
3. 中間日は巡回車の終端位置・燃料を元経路と完全一致させ、翌日の開始状態を変えない。
4. 玉数候補の成否にかかわらず、従来の系列優先・難度重み4本も独立に比較する。

玉数候補は既存解より公式得点が高い場合だけ採用する。`--small-board-quantity-first 0`で追加候補を無効化できる。

## 16×16検証

公開APIは実交通、他チームの行動、取得順を提供しないため、実戦1969の完全再現はできない。問題設定へ初日順調・以後固定mixed交通を与え、固定探索量で機能だけを交互比較した。

| 問題 | 公開目標 | 無効 | 有効 |
|---|---:|---:|---:|
| 1963 | `10/90/286` | `10/90/309` | `10/90/309` |
| 1964 | `12/72/159` | `12/72/162` | `12/72/162` |
| 1969・合成mixed | `14/112/182` | `14/111/203` | `14/111/203` |
| 1969・保存実交通 | `14/112/182` | `14/112/172` | `14/112/172` |

`runtime/simple-server/client/`には1969の設定、全8日の実交通、初期状態、提出回答と得点が保存されている。`runtime_match_benchmark`はday 0の初期状態から各日の保存交通を使い、候補自身の終端位置・燃料を次日へ引き継ぐ。当時の提出`14/108/154`に対して現在の探索は全日14系列の`14/112/172`となった。公開首位までは10玉不足する。追加した玉数候補のOFF/ONは同点で、単独の上積みは未確認である。玉数候補成功時に系列優先4パスを省く案は`14/111/156`へ退行したため撤回した。

10系列の1963と12系列の1964は対象外として従来結果を維持した。生成16×16・4台・16スポット・14系列・4日・8 seedでも双方`112/448/955`だった。必要系列を強制する単体テストでは、玉数優先ビームから2系列を満たす経路だけが採用され、返却計画の公式リプレイ一致を確認する。

```sh
python3 tests/small_board_api_benchmark.py \
  --feature quantity-first --traffic mixed-after-first \
  /tmp/procon37-1963.json /tmp/procon37-1964.json /tmp/procon37-1969.json

.build/tools/solver_benchmark --size 16 --agents 4 --spots 16 --brands 14 \
  --seeds 8 --repeats 1 --mixed-traffic --fixed-work --no-day-beam \
  --compare-small-board-quantity-first

make .build/tools/runtime_match_benchmark
.build/tools/runtime_match_benchmark runtime/simple-server/client 0
.build/tools/runtime_match_benchmark runtime/simple-server/client 1
```
