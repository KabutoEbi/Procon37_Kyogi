# 探索・合流改善の比較結果（2026-09-27）

環境はmacOS arm64、Apple clang 21.0.0、C++17、`-O2 -pthread`。各日1スレッド・300ms、マクロ有効、補給車1台固定。`baseline`は今回の4機能を無効、`improved`は巡回先と合流の再割当・迂回合流・割当キャッシュ・2スポット先読みを有効にした構成。

## 再実行

```sh
c++ -std=c++17 -O2 -pthread -Iinc tests/solver_benchmark.cpp -o /tmp/solver_benchmark
/tmp/solver_benchmark --seeds 6 --repeats 2 > normal.csv 2> normal-summary.txt
/tmp/solver_benchmark --seeds 4 --repeats 2 --mixed-traffic > mixed.csv 2> mixed-summary.txt
```

4サイズ（8/16/24/32）、4日間を実行。通常交通は各サイズ12試合、混合交通は各サイズ8試合を構成ごとに比較した。実行順は問題・反復ごとに入れ替えた。時間打切りなので固定シードでも結果は変動する。

## 最終比較

| 条件 | 構成 | 試合系列合計 | 日別系列累計の合計 | 玉数合計 | 試合時間中央値 |
|---|---|---:|---:|---:|---:|
| 通常交通・48試合 | baseline | 720 | 2830 | 5579 | 1200ms |
| 通常交通・48試合 | improved | 720 | 2827 | 7822 | 1079ms |
| 混合交通・32試合 | baseline | 480 | 1906 | 4035 | 1173ms |
| 混合交通・32試合 | improved | 480 | 1870 | 5265 | 945ms |

辞書順（試合系列→日別系列累計→玉数）で比較すると、通常交通は37勝・0同点・11敗、混合交通は22勝・2同点・8敗。玉数は通常交通で約40%、混合交通で約30%増えたが、日別系列累計の合計は減った。玉数の増加だけを得点改善とは扱わない。

通常交通では展開数が15,425,708→22,723,629。改善版の割当キャッシュは3,563,046回命中、1,751,091回計算で、命中率は約67%。探索する状態自体が異なるので、割当計算数の差は同じ仕事量での速度倍率を示すものではない。

## サイズ別の最終得点合計

表の値は`試合系列 / 日別系列累計 / 玉数`。

| サイズ | 通常baseline | 通常improved | 混合baseline | 混合improved |
|---|---|---|---|---|
| 8×8 | 72 / 288 / 730 | 72 / 288 / 742 | 48 / 192 / 486 | 48 / 192 / 492 |
| 16×16 | 144 / 576 / 959 | 144 / 564 / 1278 | 96 / 382 / 665 | 96 / 380 / 814 |
| 24×24 | 216 / 860 / 2112 | 216 / 856 / 3227 | 144 / 576 / 1545 | 144 / 576 / 2221 |
| 32×32 | 288 / 1106 / 1778 | 288 / 1119 / 2575 | 192 / 756 / 1339 | 192 / 722 / 1738 |

特に32×32の混合交通で日別系列累計が低下している。将来日の交通を探索へ渡さず、その日までの情報だけで計画している。翌日の位置・燃料や短時間探索の評価について継続調整が必要。

## 機能別の確認

混合交通・4シード・各1回の追加比較では、2店先読みを外しても日別系列累計は953→934、再割当を外しても954→937となった。別実行のため厳密な単独原因の切り分けではないが、退行をこれらの機能だけに帰属させる根拠は得られなかった。`--variant no-cache / no-coordination / no-detour / no-lookahead / no-macros`で継続比較できる。

## 正しさの確認

- 最終比較の640日次計画すべてで、前日得点込みの再シミュレーションが有効で、保存された終了状態とも一致。探索失敗によるフォールバックなし
- 時間制限なしでキャッシュ有効・無効・容量1・並列実行の計画一致を確認
- 補給車競合の修正、通常経路外の合流、複数回補給、狭いビームでの2店取得の回帰テスト成功
- `algorithm_test`のAddressSanitizer / UndefinedBehaviorSanitizerで異常なし
- 厳格ビルド、`model_test`、`solver_options_test`、公開3サイズの`sample_maps_test`、実ソルバーを含むGUIバックエンド11テスト成功

候補数・再割当回数には上限があり、全巡回順・全合流点の最適性は保証しない。本番問題での得点向上も未確認。
