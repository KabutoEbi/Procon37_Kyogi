# 玉数SA-ALNS（2026-10-09）

新しい`brain2()`で、貪欲な担当スポット割当を初期解とし、追加・削除・2-opt・同一路線内移動・巡回車間移送・交換・置換の7近傍を持つ焼きなましを追加した。探索中の現在解と最良解を分離し、系列数を維持したまま評価エネルギーが減る遷移を温度に応じて受理する。提出候補には常に最良解を返すため、初期解に対する公式辞書順得点の非退行を維持する。`brain1()`は従来の改善解だけを採用するALNSとして残す。

温度は既定で2.0から0.05への指数冷却、悪化量 `d` の受理確率は `exp(d / temperature)`。固定seedのSplitMix64を使い、`--udon-sa 0`で従来の山登り型ALNSへ戻せる。診断値 `udon-alns-accepted-moves` と `udon-alns-accepted-worse-moves` で遷移数を確認できる。

評価は候補ごとに公式`simulateDay()`を完走し、累計うどん数に加えて、終了時・日中最小燃料、低燃料時間、移動不能時間、渋滞追加時間、混雑道路滞在、実際に成立した補給回数・供給燃料・被補給巡回車数をリプレイから抽出する方式へ拡張した。系列数はハード制約のままである。定式化と正規化係数は[`brain2.md`](../inc/brain/brain2.md)に記載した。

公開499試合の追加分析後、残り1.5秒以上ではSAの前に巡回車2〜3台と最寄り補給車を同時に解放するdestroy/repairを実行する二段構成へ拡張した。共同前段は公式辞書順得点が下がる案を採用せず、その改善計画と補給時刻表をSAへ渡す。短時間では自動的に省略する。

8×8・1日・seed 1〜8・各2反復・300msの交互比較では、系列／日別系列／玉数は両方式とも `96 / 96 / 266`、勝ち／同点／負けは `0 / 16 / 0` だった。16×16・1日・seed 1〜4・各1反復・1000msでも両方式とも `48 / 48 / 118`、`0 / 4 / 0` だった。この問題集合では先行探索が既に同じ得点へ到達しており、焼きなまし単体の優位性を示す結果ではない。一方、全候補の合法性と返却スコアの非退行を維持した。

燃料・交通評価追加後に8×8・4日・mixed traffic・seed 1〜2・各1反復・300msで再比較した。公式得点は両方式とも `12 / 48 / 133`、勝ち／同点／負けは `0 / 2 / 0`。SA版は全日合計で実補給78回・供給燃料540、非SA版は67回・483だった。この小標本は補給量の一般的改善を証明するものではないが、同じ公式得点を保ちながら補給合流を評価した計画が選ばれることを確認できた。全16日次計画は公式再シミュレーションで有効だった。

`make test-core`（C++コア・公式Q&A・プロパティとPython 55件）および全C++テストのASan/UBSan実行が成功した。単体テストでは高温設定で悪化遷移が実際に受理され、その後も返却最良解の系列数・玉数と公式再シミュレーション結果が一致することに加え、Jammed道路の追加3ステップと、燃料0から同位置補給が成立するリプレイ診断を検査する。

## 残在庫・移動時間を使う近傍

追加・置換候補を最大在庫ではなく当日開始時の残在庫から選び、割当済み個数を引いて在庫が残らない店を除外した。追加・置換と1〜2店の連続区間移動／巡回車間移送では、当日の交通を含む移動時間が最短になる挿入位置を使う。評価関数には正規化した巡回車移動時間と取得時刻を小さいペナルティとして加えた。返却計画の試合系列数・当日系列数を守るハード制約と、公式辞書順の最良解保持は変更していない。

`solver_benchmark --compare-quantity-aware-sa --seeds 6 --repeats 1 --time-ms 500 --days 4 --mixed-traffic`で、8／16／24／32の4サイズ、計24試合を同条件比較した。

| 構成 | 試合系列 / 日別系列 / 玉数 | 勝ち / 同点 / 負け | 中央時間 | 最大時間 |
|---|---:|---:|---:|---:|
| 旧SA近傍 | 360 / 1440 / 5337 | — | 1936ms | 2000ms |
| 残在庫・距離対応 | 360 / 1440 / 5472 | 17 / 5 / 2 | 1965ms | 2000ms |

全24ペアで試合系列数と日別系列数は個別にも同一で、玉数は合計135増えた。300ms・4 seedの短時間比較でも系列数を維持し、`3375→3461`、`10 / 3 / 3`だった。実時間打切りの生成問題による比較なので本番全問題での改善保証ではないが、系列を犠牲にせず玉数へ寄せる既定近傍として採用した。
