# ビーム探索と焼きなましの選定（2026-10-10）

## 結論

既定解法には、ビーム探索単独ではなく、**ビーム探索で系列数を最大化した初期解を作り、系列マスクを固定した焼きなまし（SA-ALNS）で玉数を改善する構成**を採用する。

この問題の公式得点は「試合系列数、日別系列数、玉数」の辞書順である。ビーム探索は上位2指標を広く探索する役割、焼きなましは得られた系列を失わずに経路・担当を組み替えて第3指標を改善する役割に分ける。純粋な二者択一ではなく、この直列構成が比較上もっとも良かった。

既定値は `UdonAlnsConfig::simulatedAnnealing = true` であり、今回の選定と一致している。`--udon-sa 0` は比較・診断用に残す。

## 比較条件と結果

生成問題、固定seed、mixed trafficを使い、各ペアで公式シミュレーションの合法性を検査した。勝敗は公式辞書順得点で判定した。全比較で試合系列数と日別系列数はペアごとに同一だったため、差は玉数だけである。

### 短時間・全サイズ

8／16／24／32盤面、seed 1〜4、4日、各日500ms、計16試合で比較した。

| 比較 | 基準の玉数 | SA側の玉数 | 勝ち / 同点 / 負け |
|---|---:|---:|---:|
| ビーム単独相当（後段ALNSなし） vs ビーム＋SA | 3426 | 3597 | 11 / 3 / 2 |
| ビーム＋山登りALNS vs ビーム＋SA | 3439 | 3564 | 12 / 2 / 2 |

後者の盤面別成績は8×8が `2 / 2 / 0`、16×16が `3 / 0 / 1`、24×24が `4 / 0 / 0`、32×32が `3 / 0 / 1` だった。小盤面では先行ビームだけで同じ解へ到達しやすいが、24・32盤面ではSAの多様な近傍と悪化遷移受理が効いた。

再現コマンド:

```sh
.build/tools/solver_benchmark --compare-udon-alns --seeds 4 --repeats 1 --time-ms 500 --mixed-traffic
.build/tools/solver_benchmark --compare-udon-sa --seeds 4 --repeats 1 --time-ms 500 --mixed-traffic
```

### 5秒・大盤面

経路列探索を含む長時間向け処理が有効になる5秒枠で、24／32盤面をseed 1〜4、1日で追加比較した。

| サイズ | 山登りALNS | SA-ALNS | 勝ち / 同点 / 負け |
|---|---:|---:|---:|
| 24×24 | 357 | 366 | 4 / 0 / 0 |
| 32×32 | 376 | 407 | 4 / 0 / 0 |

再現コマンド:

```sh
.build/tools/solver_benchmark --compare-udon-sa --single-day --size 24 --seeds 4 --repeats 1 --time-ms 5000 --mixed-traffic
.build/tools/solver_benchmark --compare-udon-sa --single-day --size 32 --seeds 4 --repeats 1 --time-ms 5000 --mixed-traffic
```

## 採用理由

- 上位2指標を一度も落とさず、短時間全サイズで玉数を合計125、5秒の大盤面8試合で合計40増やした。
- 24×24と32×32の5秒比較では8戦全勝し、大盤面での改善が安定していた。
- SAは探索中に悪化解も受理するが、提出するのは探索中の最良解だけなので、同じ初期解に対して最終結果を意図的に悪化させない。
- ビーム探索を外してSAだけにすると、最優先の系列数を作る能力を失う。したがって、系列最大化のビームを前段に残す。

実時間打切りでは、SAの有効化によって締切直前までの探索順が変わるため、個別seedの勝利は保証できない。それでも複数サイズ・短時間と5秒枠の双方で総合的に優勢なので、既定方式はビーム＋SAとする。
