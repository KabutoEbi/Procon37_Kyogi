# 探索処理の高速化比較（2026-09-27）

macOS arm64、Apple clang 21.0.0、C++17、`-O2 -pthread`、1スレッドで測定。探索機能・重み・候補数は変更せず、最小費用流の作業領域再利用、合流計算のメモ化、迂回候補の部分ソート、時間・燃料下界による早期除外を適用した。

以下の「変更前／後」は高速化前後の実行ファイルを指す。CSVの`baseline／improved`は探索機能の無効／有効を指し、別の比較軸である。

## 同じ探索量での比較

`--fixed-work --seeds 3 --repeats 2`で8/16/24/32の4サイズ・4日間を完了まで探索した。ビーム幅32、同時行動幅128、時間制限・自動幅調整・プロファイル計測は無効。各構成96日分を比較。

| 探索構成 | 変更前の時間合計 | 変更後の時間合計 | 短縮率 | 同一の展開数 |
|---|---:|---:|---:|---:|
| 現行の4機能有効（improved） | 32,796ms | 25,023ms | 約23.7% | 8,876,020 |
| 4機能無効（baseline） | 51,558ms | 38,310ms | 約25.7% | 8,693,922 |

192日分すべてで計画ハッシュ・試合系列・日別系列累計・玉数・展開数が一致した。各日次計画は前日得点込みの再シミュレーションでも合法で、終了状態が一致した。探索失敗によるフォールバックなし。

## 300ms制限での比較

`--seeds 4 --repeats 2`、同じ4サイズ・4日間、各日300msで実行。以下は現行4機能有効の32試合（128日分）の合計。

| 指標 | 変更前 | 変更後 |
|---|---:|---:|
| 展開数 | 15,008,311 | 16,656,265 |
| 探索時間合計 | 30,838ms | 26,629ms |
| 展開数 / ms | 約487 | 約625 |
| 試合系列合計 | 480 | 480 |
| 日別系列累計の合計 | 1896 | 1882 |
| 玉数合計 | 5434 | 5462 |

展開数は約11%増加し、時間当たりの展開数は約29%増加。早く完了する問題もあるため、全日が300msを使い切るわけではない。

時間制限下では探索できる状態が変わり、計画も変わる。辞書順では14勝・4同点・14敗となり、日別系列累計の合計は下がった。高速化を一律の得点向上とは扱わない。生成問題での計測値であり、CPU負荷・実行順で時間打切り結果も変動する。

## ボトルネックの計測

別実行で`--fixed-work --profile --seeds 2 --repeats 1`を使用。現行構成の32日分で、共同割当計算は約8.82秒→5.70秒、合流の実計算は約4.07秒→2.75秒、最小費用流の実行は約1.67秒→1.20秒となった。計測範囲は重複するため加算しない。プロファイルは計測負荷を加えるので、上の速度比較からは外した。

## 比較手順

高速化前の実行ファイルを保存した後、変更後を同じコンパイル設定でビルドする。

```sh
# それぞれ変更前・変更後のソースでビルドする
c++ -std=c++17 -O2 -pthread -Iinc tests/solver_benchmark.cpp -o /tmp/procon37-speed-before
c++ -std=c++17 -O2 -pthread -Iinc tests/solver_benchmark.cpp -o /tmp/procon37-speed-after

/tmp/procon37-speed-before --fixed-work --seeds 3 --repeats 2 > before-fixed.csv
/tmp/procon37-speed-after --fixed-work --seeds 3 --repeats 2 > after-fixed.csv
/tmp/procon37-speed-before --seeds 4 --repeats 2 > before-timed.csv
/tmp/procon37-speed-after --seeds 4 --repeats 2 > after-timed.csv
```

固定探索量では同じ`size,seed,repeat,variant,day`を照合し、計画ハッシュ・得点・展開数が一致してから時間を比較する。実行順を入れ替えて反復すると、CPU負荷の偏りをさらに確認できる。
