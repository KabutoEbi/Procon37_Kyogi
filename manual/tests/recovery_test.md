# 復旧・締切管理テスト

```sh
python3 -m unittest tests/recovery_test.py
```

外部通信なしで、問題・当日状態の公開待ち、応答喪失後のプロセス再起動と同一回答再送、受理記録保存後のチェックポイント書込み失敗、未知結果の得点確定禁止、新しい探索の禁止、接続先・ファイル変更検出、締切切れ、レート制限待機後の締切検査、相対探索予算維持、ソルバー監視を検証する。

実C++ソルバーでの4日間連携は`PROCON_TEST_SOLVER`を指定した`tests/visualizer_test.py`、同梱簡易サーバーの実通信は`tests/visualizer_simple_server_test.py`で確認する。実サーバーの受理・時刻差を保証するテストではない。

同日回答の更新では、受理後に異なる回答を送り、応答が失われるケースも検証する。旧候補・旧受理履歴・旧得点の保持、同日と翌日の探索禁止、同じ更新候補の再送成功後だけ新得点を確定することを確認する。

3人運用については、担当2・3が通信timeoutを探索時間から予約せず5秒の安全余裕を残すこと、同点回答を送信しないこと、受理済みチェックポイントをrevision別に共有し、次日の状態取得後に最大revisionだけを取り込むことを検査する。POST本文とHTTPエラー本文の監査ログも確認する。
