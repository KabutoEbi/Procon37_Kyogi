# 公開試合1866までの得点分析とSA近傍誘導

取得日: 2026-10-09
取得元: `GET https://procon37arena.online/api/matches/{id}`

## 公開結果

#1367〜#1866の500試合番号を問い合わせ、`scored`かつ`verified`の499試合を集計した。取得できなかった1件は除外した。公開APIは問題設定、最終順位、試合系列数、日別系列数、玉数、回答時間を返すが、各チームの行動列、日別経路、交通履歴、巡回車／補給車の割当は返さない。以下は得点からの推定であり、上位実装の断定ではない。

| 盤面 | 試合数 | 首位の試合系列満点 | 首位の日別系列満点 | 首位の平均理論在庫回収率 |
|---:|---:|---:|---:|---:|
| 16×16 | 253 | 253 | 245 | 66.1% |
| 24×24 | 164 | 164 | 164 | 65.2% |
| 32×32 | 82 | 82 | 82 | 65.3% |

首位は499試合すべてで試合系列満点、491試合で日別系列も満点だった。上位2チームの系列指標が同じ485試合では、玉数差の中央値2、75パーセンタイル5、90パーセンタイル11で、345試合が4玉差以下だった。盤面別の平均差は16×16で2.47、24×24で5.92、32×32で11.11玉であり、大盤面ほど複数車両の経路組合せが差になっている。

首位が2位より長く回答時間を使ったのは240/499試合で、平均回答時間も首位163.8秒、2位158.4秒だった。単純な計算時間の長さより、系列被覆後の経路・在庫・補給の再配分方式が主要因と推定する。

#1866は24×24、5台、24スポット、16系列、4日、1日当たり在庫63。首位「うどん」は`16 / 64 / 172`、2位は171玉、超10Gは`16 / 64 / 160`で5位だった。超10Gの12玉差は系列数ではなく、系列満点後の玉数差である。

## 推定した探索方針

- 試合系列と日別系列を最初に満たし、以降はハード制約として維持する。
- 同じ高在庫スポットへ複数巡回車を割り当て、在庫上限まで回収する。
- 1〜4玉差を詰めるため、7種類の近傍を維持しながら、追加・置換先では在庫が残るスポットを優先する。
- 24×24以上では巡回車2〜3台と補給車を同時に破壊し、在庫所有者と合流時刻をまとめて再構築する。
- 混雑と燃料は別の近似距離ではなく公式リプレイで評価し、同点経路では燃料切れリスクと渋滞追加時間が小さいものを残す。

## brain2への反映

追加・置換先は一様乱数ではなく、`1 + 3 * 未割当在庫数 + 6 * 未割当系列`を重みにして抽選する。公式の系列数制約と`simulateDay()`検証は変更しない。

7近傍の確率を追加28%、削除4%、2-opt 20%、同一路線移動12%、巡回車間移送15%、交換12%、置換9%とする案も実装した。しかし#1866の3秒/日・固定mixed交通では、一様143玉、近傍確率だけ143玉、在庫重みだけ143玉、両方同時132玉だった。このため近傍確率変更は`arenaGuidedNeighborhoods=false`を既定とし、非退行だった在庫重みだけを有効にした。

`UdonAlnsConfig::stockWeightedSpotSelection=false`でスポット選択も一様へ戻せる。

さらにSAの前段へ共同destroy/repairを追加した。巡回車2台、24×24以上では最大3台と、主巡回車へ交通時間で最も近い補給車の suffix を解放する。切断時点の公式状態から在庫を再配分し、合流を含む全車計画を公式シミュレータで検証してからSA初期解にする。残り1.5秒未満ではSA時間を奪わないよう前段を省略する。`--udon-joint-destroy 0`で切り分けられる。

## 切り分け結果

24×24、5台（4巡回+1補給）、24スポット、16系列、4日、mixed traffic、seed 1〜4、300ms/日の生成問題で比較した。

| 方式 | 試合系列合計 | 日別系列合計 | 玉数合計 | 有効計画 |
|---|---:|---:|---:|---:|
| 一様近傍 | 64 | 256 | 851 | 16/16 |
| 在庫重み付き | 64 | 256 | **856** | 16/16 |

合計で5玉増えた。小標本かつ時間制限付き生成問題なので一般的優位性は保証しない。公開#1866そのものでは24×24・5台・固定mixed交通・補給mask 1・3秒/日・幅256/1024で、一様と在庫重みがともに`16 / 64 / 143`だった。実戦の交通と他チームの動きはAPIに含まれないため、公開首位172玉の再現値ではない。

共同destroy/repairのON/OFFも同じ#1866条件で`16 / 64 / 143`対`16 / 64 / 143`、32×32・7台・24系列・4日の生成seed 1・3秒/日で`24 / 96 / 359`対`24 / 96 / 359`だった。どちらも非退行だが、この小標本では玉数改善を確認できていない。300ms/日では前段へ時間を割くと退行したため、1.5秒の適用下限を設けた。
