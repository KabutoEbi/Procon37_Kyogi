1928/1929、1930/1931はそれぞれ同じ問題の別テーブル。下限は各日について`min(sum(min(店在庫, P)), P * daySteps)`を合計し、玉数・系列数・日別系列数の最大値を満たす最小Pから求める。距離と燃料を無視した必要条件であり、実際の構成は一意に分からない。

1931では3巡回の在庫上限が540、4巡回が630なので、596玉には最低4巡回が必要。補給を最低1台残す既定範囲では4巡回＋1補給に限られる。1928の最低2巡回という値から、上位が実際に2巡回だったとは推定できない。

## 上位戦略の仮説と追加SA

51/51ラウンドの首位は両系列指標を満点にしている。1931は4巡回の在庫上限630の94.6%に到達し、系列達成後の巡回間の在庫割当と訪問順改善が主課題と推定した。1930の首位は全日回答時間48.57秒で595玉、1931は458.01秒で596玉なので、時間を使い切ることだけで差は説明できない。公開得点から上位のSA採用や具体的な実装は断定できない。

通常SAの貪欲再構築は維持し、追加SAだけ公式再生で確定した取得スポット列を初期解として引き継ぐ。追加パスで再び空から貪欲解を作る時間を省き、挿入・移送・交換へ回す。中間日は従来の終点・燃料保存条件、採用時の公式辞書順・再シミュレーション条件を維持する。

固定探索量、順序を交互にした対比較、mixed交通、1スレッド、seed 1〜2、4日、日跨ぎビームOFF。系列数・日別系列・玉数は2試合の合計。

| 盤面 | 従来の追加SA | 訪問列を引き継ぐ追加SA | 勝 / 分 / 負 |
|---|---|---|---|
| 16×16・4台 | 24 / 96 / 250 | 24 / 96 / 250 | 0 / 2 / 0 |
| 24×24・5台 | 36 / 144 / 449 | 36 / 144 / 450 | 1 / 1 / 0 |
| 32×32・7台 | 48 / 192 / 693 | 48 / 192 / 695 | 1 / 1 / 0 |

## 公開首位との到達差と未達目標

同じ問題に固定mixed交通を与えた既存方式の500ms/日・幅128比較では、1927は補給mask 1〜8で117〜120玉、1930は補給mask 1〜16で595〜606玉へ到達した。実交通・他チームの取得・行動列はAPIにないため、公開首位107玉・596玉との比較は同一条件の勝敗ではない。

1928は差が残る。新方式の5秒/日、自動幅として扱う幅1300/5200、補給mask 8、固定mixed交通では`19/132/228`で、首位`19/133/267`に未到達だった。500ms/日の初期構成比較では1補給が187〜224玉、2補給が163〜182玉で、補給を増やすだけでは解消しなかった。時間配分15/25/35/45%の単発比較にも安定改善はなかったため配分は変更しない。

「安定して上位チーム以上」は未達。特に短い日の系列維持と在庫・経路配分を継続課題として残す。コンパイルや回帰試験と同時に走った短時間測定は、変更の採用根拠から除外した。

## ランダム探索の無制限実行修正

`solve_local()`は生成問題の`localTraffics`がある場合、種別選択へ`--selection-time-ms 0`を明示していた。C++はこれを無制限と解釈し、6候補×複数日×交通条件の試走に終了時刻がなかった。Pythonの監視も`endsAt=0`では無効だった。

ローカル種別選択の0を既定10秒へ変換し、日次予算が短い場合はさらに短縮する。普通のローカル設定にも同じ処理を使い、道路状態がない場合は全道路順調の初期状態を生成する。種別・日次のプロセス監視は上限+2秒、生成処理は30秒のtimeoutを持つ。無期限化の再発と停止不能プロセスを回帰試験で検査する。
