# 補給車の合流改善（2026-09-30）

## 変更内容

経路上で合流できる場合にも、合流待ちや燃料節約経路によって目的地到着が遅くなる場合は、経路外の合流地点を比較する。既存案を改善するための経路は事前計算済み最短路から復元し、燃料・残時間・補給車の到着時刻・補給後の経路を検証する。合流案がない場合は、従来どおり燃料制約付き探索も使う。

到着時間の下界で改善不能な候補を除外する。同じ到着時刻なら、再補給が必要な案より1回の補給で目的地へ届く案を優先する。全地形・交通で移動時間は消費燃料の2倍以下なので、最短時間が残燃料の2倍を超える合流地点は検査数上限の適用前に除外する。

燃料制約付き最短路は、目的地の最短到着時刻より遅いラベルの探索を打ち切る。同時刻のラベルは確認し、最小燃料のタイブレークを保つ。

追加改善も候補数上限に従う。既存案の改善には燃料節約経路の網羅探索を行わず、複数台・複数回補給を含む最適性は保証しない。

## 人工問題と回帰テスト

3×2の全平地、巡回車1台・補給車1台、1スポット、8ステップ、燃料上限1または2で、開始位置・補給車位置・目的地を変えた360ケースを変更前後で比較した。巡回車の開始位置と目的地が同じケースは除外し、幅1・同時行動幅1・各車の採用行動数1とした。比較は獲得数、次に最初の取得までの時間で行い、4ケースが改善、356ケースが同点、悪化はなかった。全計画は合法だった。

改善ケースでは取得が6ステップ目から4ステップ目になった。巡回車0、補給車3、目的地5、燃料1のケースを`algorithm_test.cpp`に追加し、幅1での4ステップ取得と直列・並列一致を確認する。

燃料制約付き探索は混合交通の8×8・3シードで、全通行可能目的地と燃料上限0〜6を、使用燃料順の独立した動的計画法と照合した。到達可否、最短時間、同時刻の最小燃料、復元経路の燃料・時間を検査する。

## ランダム問題の比較

Apple clang 21.0.0、C++17、`-O2 -pthread`で変更前後をビルド。8・16・24・32マス、seed 1〜3、4日間、混合交通、1スレッドで比較した。各条件1回の計測で、計測中は他のビルド・テストを実行していない。得点は`試合系列数 / 累積日別系列数 / 玉数`の順。

```sh
.build/tools/solver_benchmark --seeds 3 --repeats 1 --fixed-work --mixed-traffic
.build/tools/solver_benchmark --seeds 3 --repeats 1 --mixed-traffic
```

ツールの`baseline`と`improved`は機能構成名であり、今回の変更前後を示す名前ではない。それぞれを変更前後で比較した。

幅32・同時行動幅128、時間制限なし。

| 構成 | 変更前の合計得点 | 変更後の合計得点 | 勝 / 同点 / 敗 | 探索時間合計（前→後） |
|---|---|---|---|---|
| improved | 180 / 719 / 2132 | 180 / 719 / 2154 | 2 / 10 / 0 | 9606 → 9550 ms |
| baseline | 180 / 719 / 2175 | 180 / 719 / 2175 | 0 / 12 / 0 | 10501 → 10401 ms |

現行構成の32×32・seed 1が`24 / 96 / 218`から`24 / 96 / 236`へ、seed 2が`24 / 96 / 252`から`24 / 96 / 256`へ改善した。他の10試合は同点。約0.6%の時間差は小さく、高速化の確証とはしない。

### 1日300ms制限

| 構成 | 変更前の合計得点 | 変更後の合計得点 | 勝 / 同点 / 敗 |
|---|---|---|---|
| improved | 180 / 715 / 2161 | 180 / 701 / 2134 | 2 / 5 / 5 |
| baseline | 180 / 705 / 1981 | 180 / 704 / 1957 | 3 / 5 / 4 |

短時間制限では得点低下が残る。現行構成の32×32・seed 1は日別系列数92→87、seed 3は96→87だった。追加候補による探索順の変化と実時間打切りの影響があるため、合流の局所改善を全条件での得点改善とは扱わない。短い制限での日別系列数の維持は今後の課題とする。

固定量・時間制限それぞれについて、2構成×12試合×4日の全96回答が変更前後とも合法で、再シミュレーションした終了状態も一致した。
