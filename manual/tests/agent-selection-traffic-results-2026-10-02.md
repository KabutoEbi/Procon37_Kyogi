# 32×32・20系列の種別選択改善（2026-10-02）

32×32、7台、32スポット、20系列で、短い種別選択時間に補給車1台が選ばれ、日別系列数が伸びないケースを再現した。

## 変更

- 補給車台数は「補給車1台で巡回車およそ2台」となる中心台数から比較する。7台では2台、1台、3台の順である。
- 各台数の距離評価1位を比較した後、補給車を離した広域配置を比較する。
- 燃料上限が最長日の行動数以下で試走が時間切れし、中心台数より少ない補給車を選んだ場合は過少補給と判定する。同じ到達可能系列数を保つ中心台数の広域配置があれば、そちらを安全側の結果として使う。
- ベンチマークへスポット数・系列数の上書きと、2日目以降の道路を順調・混雑・渋滞へ振り分ける未使用交通条件を追加した。

全候補を時間内に比較できた結果、燃料に余裕がある問題、中心台数以上を選んだ問題はこのフォールバックで上書きしない。

## 結果

seed 401〜408、各日32ステップ、燃料32、選択上限5秒、固定幅8／同時行動幅32で比較した。得点は8試合の合計で、優先順は試合系列数、日別系列数、玉数である。

| 検証条件 | 変更前 | 変更後 |
|---|---:|---:|
| 全道路順調 | 160 / 388 / 442 | 160 / 404 / 458 |
| 未使用の混雑・渋滞 | 156 / 360 / 413 | 158 / 373 / 422 |

7件は選択と得点が同じだった。seed 407は補給1台`SPPPPPP`から補給2台`SPPSPPP`へ変わり、全道路順調では`20/32/37`から`20/48/53`、未使用交通では`18/32/40`から`20/45/49`へ改善した。悪化した問題はなかった。

実時間打切りの着手候補数はCPU負荷で変わり得る。この結果は生成した8問題での比較であり、全問題での得点向上を保証しない。

## 再現

```sh
make .build/tools/agent_selection_benchmark
.build/tools/agent_selection_benchmark \
  --size 32 --agents 7 --spots 32 --brands 20 \
  --seed-start 401 --seeds 8 --selection-ms 5000 \
  --constrained --mixed-traffic
```
