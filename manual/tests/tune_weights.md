# `tune_weights.cpp` の使い方

対象: [`tests/tune_weights.cpp`](../../tests/tune_weights.cpp)

固定seedのランダム問題を学習用と検証用に分け、探索の評価重みをオフライン調整する。
公式得点の優先順位（試合系列・日別系列累計・玉数）の重みは変更しない。

## 実行

```sh
make .build/tools/tune_weights
.build/tools/tune_weights > tuned_weights.txt
# 2026-10-01の変更前の重みを起点として再現
.build/tools/tune_weights --legacy-weights > tuned_weights.txt
```

既定は8・16・24・32の4サイズ、各4問題、4日間。学習はseed 1001～1004、
検証は2001～2004を使う。4問題には順調／混合交通と通常／厳しい燃料制約を組み合わせる。
小盤面は4台中1台、大盤面は8台中2台を補給車とする。燃料制約を厳しくした問題は
初日ステップ数の半分を燃料上限とする。交通情報は各日の開始時だけ探索へ渡す。

`--candidates`（既定30）、`--seeds`（各サイズの問題数、既定4）、`--beam`（既定8）、
`--joint-beam`（既定24）を指定できる。4条件を含めるには`--seeds 4`以上を使う。
全試走を1スレッド・時間制限なし・固定幅で実行する。候補探索中は
`fuelAwareWeights`による補正を無効にして、重み補正を二重に適用しない。

候補選択は学習集合のみで行い、学習集合内でも条件別スコアが初期値を下回る候補は除外する。
最後に選んだ候補を独立した検証集合で評価する。
検証では合計点に加え、交通と燃料の条件別の辞書順スコアが初期値を下回らないことを要求する。
一つでも退行した条件があれば初期重みへ戻す。標準エラーへ採用可否と学習・検証スコア、
標準出力へC++用の重み設定を出す。通常のソルバー起動時に学習を行うものではない。

採用した重みは、さらに未使用seedの時間制限付き探索で確認する。
今回の結果は[改善記録](search-improvements-2026-10-01.md)を参照。

`--evaluate-only --legacy-weights`は候補探索を行わず、現在の燃料条件別の重み補正の
有無を同じ学習・検証集合で比較する。探索本体を変更した後も採用重みの効果を再確認できる。

採用した4重みの補正は燃料上限が初日ステップ数より小さく、
有効な探索予算が300ms以下の場合に限って適用する。
一律適用では未使用問題で退行が出たため、通常燃料の問題と長時間・無期限探索は元の重みを維持した。
手動で学習結果を`beam.weights`へ設定する場合は`beam.fuelAwareWeights = false`にする。

`--tight-only`は燃料制約が厳しい問題だけを学習・検証へ含める。
`--scale-percent 120`なら候補の増減を1.2倍／1/1.2倍にする（既定150、100超400以下）。

`--time-ms 300`を指定すると、時間制限を維持して試走する。既定の固定探索量モードと違い、
実行ごとに結果が変動するため、比較は反復し、他のビルド等と同時実行しない。
短時間用補正を確認する例:

```sh
.build/tools/tune_weights --evaluate-only --legacy-weights --time-ms 300 --beam 128 --joint-beam 512
```

時間制限を指定しない`--evaluate-only`では短時間用の補正は発動せず、同じ重みの比較になる。
