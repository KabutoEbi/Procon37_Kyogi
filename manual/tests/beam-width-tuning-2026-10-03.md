# 50秒探索のビーム幅計測（2026-10-03）

注: この記録はスポット再探索追加前の実装に対するもの。現行コードの推奨値は[2026-10-04の再計測](beam-width-tuning-2026-10-04.md)を参照。

32×32・8台のローカル問題で、日1つ分の固定幅探索が50秒前後で完走するビーム幅を計測した。

## 条件

- `runtime/random-setting.json`: 32×32、8台、32スポット、20系列、10日。
- `runtime/local-state.json`: day 0、巡回車5台、補給車3台。
- C++17、`-O2 -pthread`。
- `--threads 0`で自動並列、`--time-limit-ms 0`で相対時間制限なし、`--adaptive-beam 0`で幅の自動縮小なし。
- 同時行動幅はビーム幅の4倍。各条件は1回計測。
- 時間は`/usr/bin/time -p`の実時間。探索結果の`stop=completed`を確認した。

## 結果

| ビーム幅 | 同時行動幅 | 実時間 | 探索内部の経過時間 | 展開数 |
|---:|---:|---:|---:|---:|
| 128 | 512 | 1.11秒 | 1,107ms | 797,276 |
| 1,024 | 4,096 | 7.02秒 | 7,019ms | 7,513,818 |
| 7,000 | 28,000 | 43.75秒 | 43,744ms | 61,913,263 |
| **7,700** | **30,800** | **48.27秒** | **48,269ms** | **67,989,289** |
| 8,000 | 32,000 | 52.30秒 | 52,291ms | 70,128,853 |

この問題では、50秒以内の余裕を残す設定としてビーム幅7700、同時行動幅30800を採用できる。幅8000は52.30秒で目標を超えた。

```sh
./main solve runtime/random-setting.json runtime/local-state.json \
  --beam-width 7700 --joint-beam-width 30800 \
  --threads 0 --time-limit-ms 0 --adaptive-beam 0
```

この数値は当該問顏・day 0・計測マシンに対する実測値である。日ステップ数、交通、台数、CPU負荷で所要時間は変動するため、本番では`--time-limit-ms`と安全余裕を優先する。通常の時間制限付き探索では、自動幅調整と段階的深化が有効であり、指定した初期幅だけを実行するとは限らない。
