# `app.py` の使い方

対象: [`visualizer/app.py`](../../visualizer/app.py)

Tkで取得・探索・送信を操作するGUIの入口である。リポジトリ直下から起動する。

```sh
python3 visualizer/app.py
```

## 同梱簡易サーバーでの確認

1. 「mainをビルド」で現在の`main.cpp`から実行ファイルを作る。
2. 「同梱の簡易サーバー」で設定JSON、チーム、port、種別締切、開始待ちを確認する。
3. 「起動して使用」を押す。URL、TOKEN、workがローカル確認用へ切り替わる。
4. 「通信確認（手動）」を押す。
5. 手動の1〜6、または「自動」「試合開始前から」「自動開始（送信あり）」を実行する。
6. 終了後に簡易サーバーの「停止」を押す。ウィンドウを閉じた場合も停止する。

種別締切は起動時から進む。手動操作では余裕のある秒数にする。簡易サーバーは`127.0.0.1`だけで待ち受け、選択した設定内のTOKENを入力欄へ設定する。`.env`は書き換えない。

## 実サーバーでの手動操作

URLとTOKENを入力し、通信確認後に次の順で操作する。

1. 試合設定を取得
2. エージェント種別を選択
3. エージェント種別を送信
4. 当日状態を取得
5. 日次探索を実行
6. 日次回答を送信

dayは0始まりである。day 1以降の探索には、直前の回答が受理された後に確定した`score-dayN.json`が必要となる。手動POSTの前には確認ダイアログを表示する。

## 自動操作

- 「試合開始前から」は設定取得、種別選択・送信、全日の取得・探索・送信を行う。
- 「対象dayから」は種別送信済みの試合を指定dayから処理する。
- 「停止位置から再開」は同じGUIプロセス内で停止した段階から再開する。

HTTP 403、未公開の古いday、接続失敗は設定した上限まで待つ。401、先の日への進行、POST失敗は停止する。POST失敗は二重送信防止のため自動再送しない。

## 表示と安全性

- マップタブは地形、混雑・渋滞、スポット系列、P/S、位置・燃料を表示する。
- JSONタブは設定、状態、種別、回答、次日得点を表示する。
- 探索パラメータは実行開始時に[`solver_options.hpp`](../inc/solver_options.md)用CLI引数へ変換する。
- HTTPとソルバーはバックグラウンドで実行し、Tk部品の更新だけをメインスレッドで行う。
- TOKENは入力欄で伏せ、ログへ現れた同じ文字列も置換する。

画面が空白になる場合は[`runtime.py`](runtime.md)の実行環境確認を行う。
