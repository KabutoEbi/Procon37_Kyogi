# `app.py` の使い方

対象: [`visualizer/app.py`](../../visualizer/app.py)

Tkで取得・探索・送信を操作するGUIの入口である。リポジトリ直下から起動する。

```sh
python3 visualizer/app.py
```

## 同梱簡易サーバーでの確認

1. 「mainをビルド」で現在の`main.cpp`から実行ファイルを作る。
2. 左端の「簡易サーバー」チェックを入れ、右側に表示される設定JSON、チーム、port、種別締切、開始待ちを確認する。
3. 「起動して使用」を押す。URL、TOKEN、workがローカル確認用へ切り替わる。
4. 「通信確認（手動）」を押す。
5. 「設定取得・種別選択・送信」を押し、対象日の「当日状態を取得・探索」へ進む。日次回答の送信方法は画面上部で選ぶ。
6. 終了後に簡易サーバーの「停止」を押す。ウィンドウを閉じた場合も停止する。
7. 新しい試合を始める場合は、停止中に「作業フォルダをクリア」を押して、前回の取得データ・回答・送信記録を削除する。

種別締切は起動時から進む。手動操作では余裕のある秒数にする。簡易サーバーは`127.0.0.1`だけで待ち受け、選択した設定内のTOKENを入力欄へ設定する。`.env`は書き換えない。
クリア対象は`runtime/simple-server/client/`の中身だけで、サーバーログと設定JSON原本は残る。実行前に確認ダイアログを表示し、簡易サーバーの実行中はボタンを無効化する。

## 試合操作

メイン画面の「実行設定・使用ファイル」から専用ウィンドウを開き、URLとTOKENを入力する。設定ウィンドウを閉じても入力値は保持される。通信確認後、メイン画面で次の順に操作する。

1. 「mainをビルド」を手動で押す。
2. 「設定取得・種別選択・送信」を手動で押す。設定取得、`agents.json`作成、種別のPOSTを順に実行する。
3. 「当日状態を取得・探索」を手動で押す。対象dayの状態取得から`answer.json`と`score-next.json`の生成までを続けて実行する。
4. 回答送信が「手動」なら確認して「日次回答を送信」を押す。「探索後に自動」なら探索成功後に確認ダイアログなしで送信する。
5. 受理後、対象dayが次へ進む。次の日は3から繰り返す。

dayは0始まりで、設定取得時に0へ戻り、入力範囲は`daySteps`の日数に合わせる。マップ上部では総日数を`days`、当日状態から取得する現在日を`day`として別々に表示するため、状態取得前は`day=未取得`でも`days`には設定済みの日数が表示される。day 1以降の探索には、直前の回答が受理された後に確定した`score-dayN.json`が必要となる。手動の回答POSTの前には確認ダイアログを表示する。

設定を読み込むと、`startsAt`を試合開始予定として実行ログへ表示し、`daySeconds`を順に加算して「1日目終了予定」以降の全日程も表示する。開始時刻が0なら未確定とし、各日終了予定は試合開始からの累積秒数で示す。

簡易サーバー起動時は「種別締切(s)」と「開始待ち(s)」を基準に時刻を監視する。到達時に`⏰ 選択時間終了`、`⏰ 試合開始`を出力し、その後は設定JSONの`problem.daySeconds`に従って`⏰ 1日目終了`、`⏰ 2日目終了`のように出力する。簡易サーバーを停止または作業フォルダをクリアすると、未到達の通知を取り消す。

GUIは次の日の探索を自動では始めない。送信失敗時も自動再送せず、結果不明の送信記録を保護する。送信確保時間・時刻余裕は探索パラメータ画面で指定する。別試合は新しい作業フォルダを使う。送信しないローカル設定の探索は「実行設定・使用ファイル」から実行できる。

## 表示と安全性

- マップタブは地形、混雑・渋滞を表示し、右側の状態表にエージェントの種別・位置・燃料とスポットの系列・在庫を表示する。ローカル設定の探索完了後は`result-state.json`を読み込み、状態表とマップ上のエージェントを探索後状態へ更新する。
- 探索完了後は各車の移動経路を別の色で表示する。線、マップ上の個体、一覧は同じ色を使い、次の探索開始時に線を消す。
- ワークフロー直下の探索結果枠には、対象day、終了理由、探索時間、展開ノード数、その日の総獲得数、全日程の合計獲得数、当日と全日程の獲得系列数を表示する。ローカル探索と日次探索の両方で更新する。
- ワークフローと探索パラメータは固定パネルにまとめ、通常の画面サイズではスクロールなしで操作できる。
- マップは表示領域へ自動的に縮小・中央配置し、収まる場合はスクロールバーを隠す。
- 実行ログは画面最下部へ横幅いっぱいに表示する。
- ワークフローは左側の細い操作パネルにまとめる。
- 実行設定と使用ファイルは専用ウィンドウに分離し、メイン画面右上のボタンで開く。
- JSONと実行ログのスクロールバーも、内容が表示領域を超えた場合だけ表示する。
- JSONタブは設定、状態、種別、回答、次日得点を表示する。
- 探索パラメータは実行開始時に[`solver_options.hpp`](../inc/solver_options.md)用CLI引数へ変換する。
- HTTPとソルバーはバックグラウンドで実行し、Tk部品の更新だけをメインスレッドで行う。
- TOKENは接続内容を確認できるよう入力欄へ通常表示する。画面共有時の映り込みに注意する。GUIログへ現れた同じ文字列は引き続き置換する。

画面が空白になる場合は[`runtime.py`](runtime.md)の実行環境確認を行う。
