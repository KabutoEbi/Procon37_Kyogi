# `visualizer/` の使い方

対象: [`visualizer/`](../visualizer/)

取得、探索、送信をGUIから操作し、マップやJSON、実行ログを確認するためのデスクトップアプリである。初期設定と日次探索は手動で開始し、日次回答の送信方法を手動／探索後自動から選べる。

```sh
python3 visualizer/app.py
```

macOSのシステムPythonが古いTk 8.5を使用する場合は、対応するTkを持つインストール済みPythonへ自動で切り替える。`python3 visualizer/app.py --check-runtime`で選択されたPythonとTkを確認できる。詳しくは[`runtime.py`](visualizer/runtime.md)を参照。

詳しい操作順と生成物は[`visualizer/README.md`](../visualizer/README.md)を参照する。

## ファイル別マニュアル

- [`app.py`](visualizer/app.md): 画面構成、試合操作、簡易サーバー操作
- [`backend.py`](visualizer/backend.md): 通信・ソルバー・簡易サーバー・チェックポイント管理
- [`runtime.py`](visualizer/runtime.md): macOSでのPython/Tk実行環境選択

メイン画面の「実行設定・使用ファイル」から専用ウィンドウを開き、TOKEN欄を直接編集して「通信確認（手動）」を押すと、GETで接続を確認できる。起動だけでは通信しない。トークンは入力欄では通常表示し、GUIログでは伏せる。

実サーバーを使わない確認では、画面上部の左端にある「簡易サーバー」チェックを入れ、右側に表示される設定でJSONとチームを選んで「起動して使用」を押す。URL、TOKEN、作業フォルダがローカル確認用へ切り替わり、以降は通常と同じ操作を使える。種別締切はサーバー起動時から進むため、余裕のある秒数を設定する。停止ボタンまたはGUI終了で子プロセスを停止する。新しい試合で同じ保存先を使う場合は、停止中に「作業フォルダをクリア」を押す。実サーバー用`.env`は上書きしない。

「mainをビルド」を手動で押し、「設定取得・種別選択・送信」で初期設定をまとめて実行する。各日は「当日状態を取得・探索」を押す。日次回答はボタンで確認して送るか、探索成功後の自動送信を選ぶ。初回取得後は「探索」へ切り替わり、同じ日の開始状態で再探索できる。送信後も対象dayを維持し、日終了時刻を過ぎると翌日に進む。翌日の初回取得・探索は再びボタンで始める。対象dayの範囲は試合設定の日数に合わせる。

「探索パラメータ」タブでビーム幅、同時行動幅、スレッド数、時間上限、マクロ行動、種別選択試走などを指定できる。C++側は[`solver_options.hpp`](inc/solver_options.md)で引数を読み取る。既定の種別選択は補給車を少なくとも1台含める。処理中も画面は応答し、当日状態の取得ごとにマップとエージェント・スポット表を更新する。探索完了時は各車の移動経路を色分けして表示し、次の日の探索開始時に消す。ローカル設定の探索後は、右側の状態表も終了時の位置・燃料・残在庫へ更新する。

簡易サーバーを使う場合も先に`main`をビルドする。サーバーを起動した時点から種別締切の時計が進むためである。起動後の成果物は`runtime/simple-server/client/`、サーバーログは`runtime/simple-server/simple-server.log`へ保存する。
