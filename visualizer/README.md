# Procon37 Control Center

回答システムからの取得、エージェント種別選択、日次探索、送信を手動／自動で操作するTkアプリである。公式JSONのマップ、交通状態、自チームの位置・燃料、生成JSON、実行ログも確認できる。

## 起動

リポジトリ直下で実行する。

```sh
python3 visualizer/app.py
```

Python 3.9以降とTkを使用する。`tkinter`がない場合は、使用するPythonに対応するTkパッケージを追加する。新しい探索オプションを使用するため、最初にGUIの「mainをビルド」で実行ファイルを更新する。

macOSではTk 8.6以降を使用する。`python3`が古いシステムTk 8.5を使っている場合は、起動時にインストール済みのHomebrew版／python.org版Pythonを探し、対応するTkを持つPythonへ自動的に切り替える。新たなパッケージのインストールは行わない。

ウィンドウ全体が空白になる場合は、古いウィンドウを閉じて上記コマンドで再起動する。次のコマンドなら、画面を開かずに切り替え後の実行環境を確認できる。

```sh
python3 visualizer/app.py --check-runtime
```

対応するPythonがない場合は、空白のウィンドウを作らずターミナルに理由を表示する。Apple提供の古いTkについては[Python公式のmacOS向け説明](https://www.python.org/download/mac/tcltk/)も参照。

## 同梱の簡易サーバーで確認

実サーバーへ接続しなくても、画面上部の左端にある「簡易サーバー」チェックから取得・探索・送信を一通り確認できる。チェックを入れると右側に設定が表示され、本番利用時は未チェックのまま隠しておける。

1. 先に「mainをビルド」を押す。簡易サーバー起動後は種別締切までの時間が進むため、ビルドを先に済ませる。
2. 通常は設定JSON、チーム、port、時間を初期値のままにする。
3. 「起動して使用」を押す。OS/CPUに合う同梱バイナリを選び、`127.0.0.1`だけで待ち受ける。
4. URL、TOKEN、作業フォルダが簡易サーバー用に自動で切り替わったことを確認する。
5. 手動なら「通信確認（手動）」から通常の1〜5を順に操作する。自動なら「自動」へ切り替え、「試合開始前から」で開始する。
6. 終了後に「停止」を押す。GUIを閉じた場合も同梱サーバーは停止する。

初期設定は`回答システムに関する情報・簡易版の回答用サーバー/試合設定用JSONファイル/example.json`、チームは`team-0`、URLは`http://127.0.0.1:8080`である。種別締切は簡易サーバー起動時から進む。手動確認で間に合わない場合は起動前に「種別締切(s)」を増やす。起動後の時間設定は変更できないため、停止して起動し直す。

簡易サーバー本体の出力は`runtime/simple-server/simple-server.log`、クライアント側の取得物・回答・通信ログは`runtime/simple-server/client/`へ分離して保存する。入力した実サーバー用TOKENや`.env`は変更しない。

## 手動操作

1. URLとTOKEN入力欄を設定する。`.env`の値を初期表示するが、直接入力した値がその実行で使われる。TOKENは通常表示するため、画面共有時は注意する。入力値は`.env`へ自動保存しない。
2. 「通信確認（手動）」を押す。`GET /setting`を1回実行する。HTTP 200で問題形式を確認できれば成功、403なら到達済み・公開前または権限不足、401なら認証失敗として表示する。起動時に通信確認を自動実行しない。
3. 「試合設定を取得」で`GET /setting`を行う。
4. 「エージェント種別を選択」で`agents.json`を作る。
5. 内容を確認して「エージェント種別を送信」を押す。
6. 対象dayを指定して「当日状態を取得・探索」を押す。状態取得に続けて`answer.json`と`score-next.json`を作る。
7. マップ、ログ、JSONを確認して「日次回答を送信」を押す。
8. 受理後は対象dayが1増える。6〜7を最終日まで繰り返す。

dayは0始まり。問題取得時はスポット・初期配置を、種別選択後はP/Sを、各日取得時は交通と現在位置・燃料を表示する。問題を切り替えると前の状態表示をクリアする。

手動送信では確認ダイアログが表示される。日次回答が受理された後だけ、予測得点`score-next.json`を`score-dayN.json`として次日に引き継ぐ。送信する回答・接続先・当日状態は探索時の記録と照合する。停止／失敗した探索の旧回答やローカル探索の回答は、GUIの日次送信には使用しない。

## 自動操作

「自動」を選び、開始位置を指定して「自動開始（送信あり）」を押す。開始後は各POSTの確認ダイアログを省き、送信まで自動で行う。

- **試合開始前から**: 問題取得 → 種別選択 → 種別送信 → day 0から最終日まで状態取得・探索・送信。
- **対象dayから（種別送信済）**: 問題を取得し、指定したdayから日次処理を開始する。種別は再送しない。day 1以降は対応するscoreファイルが必要。
- **停止位置から再開**: このGUIで保持している自動処理の続きから再開する。同じ接続先・TOKEN・作業フォルダを使う。

古いdayやHTTP 403、接続失敗が返る間は公開を待つ。401や期待日より先の日を検出した場合はエラーで停止する。POST失敗時は自動再送しない。受理状況を確認し、手動操作で続行する。

「停止」または実行中の「手動」への切り替えで停止を要求する。探索プロセスは終了し、再開時にその探索をやり直す。実行中のHTTPは応答またはタイムアウトを待つ。受理済みの送信は取り消さず、成功した段階の次から進む。GUIを閉じた後は停止段階を保持しないので、「対象dayから」と保存済みチェックポイントを使用する。

## 探索パラメータ

「探索パラメータ」タブで変更する。値は実行開始時に固定し、`main`のCLIオプションへ渡す。

| 設定 | GUI初期値 | 備考 |
|---|---:|---|
| ビーム幅 / 同時行動幅 | 128 / 512 | 1以上 |
| スレッド数 | 0 | 0: 自動、1: 直列 |
| 探索時間上限 | 5000 ms | 0: 相対制限なし。配布状態の締切も使用 |
| 締切余裕 | 1000 ms | 探索・種別選択の締切から差し引く |
| 各車の行動候補数 | 4 | 0: 全候補 |
| マクロ行動 / ビーム幅自動調整 | 1 / 1 | 1: 有効、0: 無効 |
| 種別選択の試走候補数 | 8 | 0: 距離評価のみ |
| 種別選択の試走幅 / 同時行動幅 | 32 / 128 | 1以上 |
| 種別選択時間上限 | 60000 ms | 試合開始時刻も締切に使用 |
| 自動取得間隔 / 公開待ち上限 | 0.5 / 3600秒 | 間隔は0.2秒以上 |

自動調整が有効な場合、実際のビーム幅は状況に応じて絞られる。指定幅で比較する場合は「ビーム幅自動調整」を0にする。時間上限以下の余裕時間を設定すると、探索が即時終了する場合がある。

ローカル確認では「使用ファイル」の「開く」から`sample_maps/`の設定JSONを選び、「ローカル設定を探索」で初期状態から回答を生成できる。この操作は送信しない。GUI自体は他チームの交通量を探索へ追加せず、C++ソルバーと同じく当日配布された道路状態を表示・使用する。

## ファイル

- `app.py`: Tk GUI、バックグラウンド実行、マップ描画
- `backend.py`: 通信、ソルバー起動、簡易サーバー管理、チェックポイント確定、JSON表示モデル
- `runtime.py`: macOSの対応Tkを持つPythonの検出と起動切り替え
- リポジトリ直下の`runtime/`: 取得JSON、回答、通信ログ、探索結果の照合記録。Git管理対象外

使用ファイルは上部の実行設定で指定し、実行ログは画面最下部へ横幅いっぱいに表示する。左側のワークフローは幅を抑え、マップ右側ではエージェントとスポットの状態を一覧できる。ワークフローと探索パラメータは固定パネルで、マップは領域に合わせて縮小する。マップ、JSON、実行ログのスクロールバーは内容が枠を超えた場合だけ表示する。

## テスト

GUIを表示せずバックエンドを検査できる。

```sh
python3 -m unittest tests/visualizer_test.py
python3 -m unittest tests/visualizer_runtime_test.py
```

実ソルバーを使った4日分の連携と途中日からの続行も検査する場合:

```sh
c++ -std=c++17 -O2 -pthread main.cpp -o /tmp/procon37_gui_main
PROCON_TEST_SOLVER=/tmp/procon37_gui_main python3 -m unittest tests/visualizer_test.py
```

デスクトップに接続できる環境ではGUIの操作テストも実行できる。これらのテストはHTTPをモック化し、実トークンを使用しない。

```sh
python3 tests/visualizer_gui_test.py
```

同梱簡易サーバーと実C++ソルバーでday 0の回答受理まで検査する場合:

```sh
c++ -std=c++17 -O2 -pthread main.cpp -o /tmp/procon37_simple_test
PROCON_TEST_SIMPLE_SERVER=1 \
PROCON_TEST_SOLVER=/tmp/procon37_simple_test \
python3 -m unittest tests/visualizer_simple_server_test.py
```
